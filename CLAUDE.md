# CLAUDE.md (cquarry)

Per-project guidance. Overrides the global file where they conflict.

## What this is
The canonical SQLite database layer and search grammar engine for Calibre; every read path is strictly read-only, and writes exist only behind the explicit opt-in `cquarry.write` module. Extracted from CalibreQuarry to serve as a shared backend for Hermitage, Wings (Carrel), bindery-cli, and the CalibreQuarry CLI.

## Hard constraints
- **No external dependencies.** Must run on pure Python 3.14+ standard library (`sqlite3`, `re`, `json`).
- **Read-only by design.** `CalibreDB` NEVER writes to `metadata.db`. The only sanctioned mutation path is the separate opt-in module `cquarry.write.WritableCalibreDB`; never add write methods to `CalibreDB`, and never import `cquarry.write` from read-only code.
- **Perfect Parity.** `cquarry.search.SearchEngine` must behave exactly like Calibre's native search bar. This includes edge cases like implicit AND evaluation, dot-delimited hierarchical tag search, identifier routing, exact match prefixing (`=`) with `.`/`..` component modifiers on every text field, multi-valued count operators (`tags:#>3`), language canonicalization, and strict errors for unknown virtual libraries / saved searches. Documented deviations live in spec.md §5; do not silently add more.
- **Performance.** `get_all_books()` executes an optimized 6-JOIN query over `books` and hydrates the list-typed fields in Python, then caches it. `SearchEngine` queries the cache, rarely the disk.

## Programmer-facing contract notes
- **List-typed fields.** `get_all_books()` / `get_book()` expose `authors`, `tags`, `languages`, `formats` as native `list[str]` (never comma-joined strings). Downstream code must NOT `.split(",")` them. Multi-valued custom columns are native lists end to end too (1.16): `field()` and `load_custom_column()` return `list[str]`, and `set_custom_column` treats a bare string as ONE value rather than comma-splitting it, so `Doe, John` survives as a single value.
- **Rows include `size`, `uuid`, `identifiers`.** `get_book()` and `get_all_books()` rows are shape-identical: both carry `size` = SUM(data.uncompressed_size) (may be None on odd schemas), per-book `uuid` ("" on schemas predating the column), and the `identifiers` EAV dict. Never add a field to one and not the other.
- **Languages follow `item_order`.** A book's `languages` are ordered by `books_languages_link.item_order` (link-id tiebreaker); pre-`item_order` schemas degrade to link-id order; Calibre's ordering contract.
- **Strict VL/saved-search errors.** `search("vl:X")` raises `ParseException` when X is unknown; only `resolve_vl()`/`resolve_saved_search()` raise `ValueError` with an available-names message. Unknown field locations and unknown `@Names` match NOTHING (empty set); never an `all:` text sweep; that is upstream behavior too. Corrupt or non-dict `virtual_libraries`/`saved_searches` preference payloads degrade to empty dicts (1.16); reads never crash on them, and ancient schemas missing the `identifiers`/`comments` tables degrade on `get_book()`/`search()` exactly like `get_all_books()` does.
- **`refresh()` is the coherence boundary.** All caches are lazy and normally never invalidate; a long-lived holder (Hermitage/Carrel keep a connection open) must call `refresh()` after an external write or its caches contradict each other (and the database). New caches must be added to `_init_caches()` so `refresh()` covers them.
- **`#label_index` is real for custom series columns (1.18; writable 1.26).** `load_custom_column` selects the link table's `extra` float and stashes it under the derived `#<label>_index` token; `_custom_value` resolves the suffix against the base series column, so `#myseries_index:>3` matches. An exact label literally ending in `_index` keeps the token (exact labels always win); ancient link tables without `extra` degrade to None. Since 1.26 the WRITER side is real too: fresh series assignments seed `extra` at 1.0 (upstream's creation default) and `set_custom_series_index(book_id, label, index)` updates the link row in place (`None` -> 1.0). The normalized value tables' `link` URL column rides the same SQL: read it via `custom_column_links(col_name)` -> `{book: url}`, never by folding it into load_custom_column's contract-frozen return.
- **User categories search via `@Name`.** `@Name:query` mirrors upstream `get_user_category_matches` (exact match on each member's own location; leading `.` includes subcategories; `false` inverts; other query text ignored; <2-char queries match nothing). Groups and real fields win over same-named categories. Providers opt in via the optional `user_categories()` hook.
- **Raw comments are HTML.** Anything rendered must pass through `helpers.strip_html()` first.
- **Writes must queue OPF resync.** Every `WritableCalibreDB` mutation inserts the book id into `metadata_dirtied` (Calibre regenerates sidecar `.opf`s only for queued ids). New write APIs MUST route through `_touch_book()`/`_mark_dirty()`; never bump `last_modified` alone.
- **`batch()` owns the commit inside its block.** Inside `with wdb.batch():`, setters defer their per-call commit and skip their own rollback; any failure rolls back the whole pass, and the failure poisons the pass: an inner batch's exception caught by the caller still rolls back at the outermost exit, never commits. `_begin()`/`_commit()`/`_rollback()` guard on `_batch_depth`; new setters get this for free by using the helpers. Never call `self.conn.commit()` directly in a setter. `transaction()` is the kept pre-1.7 alias of `batch()` (restored in v1.7.1 after a phase-3 import hit `AttributeError` on the missing name); prefer `batch()` in new code. Rollback paths catch `BaseException` (a Ctrl-C mid-set unwinds instead of committing a torn edit), and outside a batch the context-manager exit rolls back whenever an exception is in flight; its commit failures propagate like `batch()`'s do. A post-commit flush failure propagates only AFTER the batch state resets (1.20.1): `_batch_dirs`/`_batch_poisoned` clear in a nested finally, so a later failed exit can never rmtree directories of already-committed books, and `_remove_book_dir` is idempotent (a retried flush skips directories already gone).
- **Filesystem compensation is batch-scoped.** `add_book` tracks the directories it creates inside the current outermost `batch()`; a failed outermost exit removes them all (rollback alone would strand earlier books' directories as orphans). Adds made outside any batch never register, so a later failed batch cannot touch committed books' directories. New file-creating write APIs must follow the same rule: register on `_batch_dirs`, compensate only at the outermost exit.
- **`remove_book`'s file story (1.17).** `delete_files=None` (default) is rows-only; `"trash"` moves the book directory into the library-local `.caltrash/b/<id>/` (upstream's own layout), `"permanent"` rmtree's it. The fs step lands only after the rows COMMIT; inside a `batch()` it defers to the outermost commit via `_pending_removals`, so a rollback never leaves resurrected rows fileless. New file-removing APIs must follow the same commit-then-fs rule.
- **`set_format` (1.17).** Sanctioned remove+add of one `data` row in a single transaction (honest no-op when identical); the file swap stays the caller's atomic-replace job.
- **`update_title`/`set_authors` re-lay the on-disk layout (1.18).** Both setters recompute the `Author/Title (id)` directory and `Title - Author.ext` format stems with the add_book helpers, update `books.path`/`data.name` in-transaction, and apply the fs half (dir rename, file renames, emptied-parent removal) only after the commit -- inside a batch deferred via `_pending_relayouts` to the outermost commit, for a bare setter flushed right after its own commit (1.20.1: a failed commit leaves rows and files in agreement, and never leaves its fs op queued), dropped on rollback. Stale target dirs are removed (ids are unique in paths); case-only spellings use the per-segment fix; path-less rows get the db-only correction. Batch rollback also clears `_pending_removals`/`_pending_relayouts` (never flush a failed pass's queue later).
- **Entity-wide renames/removals (1.19).** `rename_entity(kind, old, new)` and `remove_entity_everywhere(kind, name)` cover authors/series/publishers/tags only (ratings have no name; languages out of scope). Name resolution is exact-spelling-first with a lowest-id NOCASE fallback. A rename whose `new` matches another row MERGES: colliding links drop against the survivor's UNIQUE(book, fk), the old row is deleted; author merges recompute `books.author_sort` and re-lay paths, series merges renumber incoming books to max+1 over the survivor's OTHER books (the moving book's stale index does not count). Series removal resets `series_index` to 1.0 like `set_series(None)` (the column is NOT NULL in real libraries; 1.0 is the schema's no-series value, never NULL). Every affected book is touched + queued; the whole verb runs inside its own `batch()`, so fs re-lays land post-commit and nested batches compose.
- **Link/sort column writers (1.25; 1.26 refinements).** `set_author_sort_name(name, sort, *, update_books=True)` writes the row-level `authors.sort` verbatim (empty raises) and recomputes every affected book's `books.author_sort` " & "-joined in link order, the same computation `set_authors` performs; an equal stored sort is an honest no-op touching no book (1.26), and `update_books=False` (1.26, upstream's postprocess shape) writes the sort ROW only, leaving every book's `author_sort` and the queues untouched. `set_link_map(kind, value_to_link, *, only_set_if_no_existing_link)` is the generic per-value link writer: the four entity kinds plus custom columns by `#label` (the normalized value table's `link` column; direct-storage columns raise). Names resolve exact-spelling-first with NOCASE fallback; unknown values RAISE where upstream skips silently (named deviation -- a link aimed at a misspelling should not vanish); `None` clears; an equal link is an honest no-op. Both verbs run in their own `batch()` and touch + queue every affected book.
- **Blob writers (1.25; 1.26 shapes).** `set_plugin_data` / `set_conversion_options` / `set_book_storage` store payloads over the three sidecar-shaped tables (plugin metrics, conversion recipes, viewer localStorage): upstream's json.dumps serialization (EVERY payload since 1.26; the 1.25 str-verbatim shortcut stored strings upstream's json.loads reader cannot decode) / upstream's deterministic protocol-2 BINSTRING frame around the caller's payload (`b'\x80\x02T'` + LE length + payload + `b'.'` -- written as plain bytes, no pickle module, and required for Calibre's unpickling reader to see the row at all) / the bare str->str JSON map in the data column (the timestamp lives in its own column; validated like upstream's rule, newest-timestamp-wins) respectively, `None` deletes, none of them queue OPF resync or touch the book (matching upstream's writers). The copy primitive's conversion-option carriage rides `set_conversion_options` (unwrapped from the source's stored frame, re-framed by the writer); plugin data is not copied, matching upstream's copy_one_book.
- **Cross-library copy (1.25).** `WritableCalibreDB.copy_book_from_library(src_db, book_id, *, preserve_timestamp=True)` is the blessed composition (upstream `copy_one_book`): ONE `batch()` on the destination, format FILES ride `add_book`'s seed path, per-author sorts then the book-level `author_sort` verbatim, timestamp preserved unless `preserve_timestamp=False`. Not carried, each named: annotations (decline), data/ extras, custom columns + uuid (the source-OPF / always-fresh rules); plugin data and conversion options ride the same release's blob writers. Duplicate policy is the frontend's; byte-identical re-imports raise through add_book's invariant.
- **Data-directory (extra-files) verbs (1.25).** `list_data_files`/`get_data_file` read the book's `data/` dir; `add_data_file`/`rename_data_file`/`remove_data_files` write it -- PURE FILESYSTEM like the trash verbs: no database rows exist for extra files, so nothing is queued, dirtied, or batch-scoped. Both sides share the traversal guard (absolute, `..`, empty components raise ValueError); upstream's `merge conflict[N]` auto-rename layout is reproduced; remove is permanent-only (the recycle bin is GUI state). `merge_extra_files` deliberately does not exist (the copy primitive excludes data/ extras).
- **`set_pages` (1.25).** The page-count row writer (upstream `set_pages`): one `books_pages_link` row per book (the book column is the table's PRIMARY KEY, so an existing row replaces), `needs_scan` lands 0 -- a recorded value is what the pending rescan waited for. The read-side `#pages` custom-column fallback is untouched; pages writes are native-table only.
- **Passthrough sort setters (1.19).** `set_author_sort`/`set_title_sort` store verbatim corrections (empty raises); `set_timestamp` normalizes like `set_pubdate`. A later `set_authors`/`update_title`/author rename RECOMPUTES over the override by design -- the passthrough is for hand-tuned corrections, not a lock.
- **Cover management (1.19).** `set_cover(book_id, data)` writes cover.jpg/cover.png by the add_book sniff-or-raise rule (no stdlib image conversion: an unparseable image raises, it is not transcoded) and removes any stale cover under the other extension; `remove_cover` sweeps both extensions and clears `has_cover`. Both defer their file work to the outermost commit via the `_pending_fs_ops` closure queue (flushed after COMMIT, dropped on rollback, alongside `_pending_removals`/`_pending_relayouts`).
- **Original-format save/restore (1.19).** `save_original_format(book_id, fmt)` copies the format as an ORIGINAL_<FMT> data row + `<stem>.original_<ext>` file (upstream's own layout, so Calibre sees it natively; saving an original of an original raises). `restore_original_format(book_id, "ORIGINAL_<FMT>")` swaps the bytes back, keeps the target's filename stem, and removes the original row, file, and FTS queue entry. Restore queues the restored format for FTS re-extraction unconditionally (INSERT OR IGNORE dedupes): the bytes changed even when set_format honest-no-opped. File work defers via `_pending_fs_ops`.
- **Trash lifecycle (1.20).** `list_trash()` / `empty_trash()` / `expire_trash(older_than=)` manage `.caltrash`'s b/ and f/ categories (upstream layout; 14-day default age, timedelta accepted, <= 0 expires all). Pure filesystem verbs: trashed rows are already gone, so nothing here touches the database.
- **Restore-from-trash (1.24).** `copy_format_from_trash(book_id, fmt, dest)` / `copy_book_from_trash(book_id, dest)` are the rescue halves (pure filesystem copies out of `.caltrash`; format entries store files under their bare extension). `move_format_from_trash(book_id, fmt)` undeletes one format into its live book (surviving-stem rule, `_pending_fs_ops` placement, FTS re-extraction queue, entry removed once only `metadata.json` remains). `delete_trash_entry(book_id, category)` rmtrees one entry (category `'b'`/`'f'`, honest False when absent, never materializes the tree). `move_book_from_trash(book_id)` rebuilds the row from the entry's sidecar `metadata.opf` (Calibre's own backup, parsed with stdlib ElementTree by local name; the OPF is READ, never generated): title + title sort, authors with the OPF's `author_sort` stored verbatim over the recomputed one, tags, identifiers (the uuid scheme becomes the preserved per-book `uuid`), comments, publisher, languages, pubdate, timestamp, series + index, rating (the OPF's internal 0-10 round-trips verbatim through the star-taking `set_rating`); every other extension-bearing file re-registers in `data` and queues FTS re-extraction; a cover file sets `has_cover`; the directory moves back only after the rows COMMIT (a rollback drops the move and keeps the entry). The id must NOT exist (upstream's rule); a missing entry or OPF raises. Custom-column values, annotations, and plugin data are NOT restored: the sidecar OPF carries only core metadata, and annotation writes are a recorded decline.
- **Custom-column schema management (1.20).** `create_custom_column(label, name, datatype, *, is_multiple, editable, display)` mirrors upstream's DDL (storage patterns per the writer's Pattern A/B split, fkc triggers, the series extra column, the tag_browser views including the filtered_ one; label rules are upstream's lowercase word chars). Column numbers allocate past the highest row id AND storage-table number so a new column never collides with a purge-pending flag-deleted column's tables. `delete_custom_column(label)` only sets mark_for_delete=1 -- the physical purge is Calibre's next-startup job, and the flagged column stays listed and functional until then (the reader's documented faithfulness). Created columns work end to end immediately; long-lived readers need refresh(). `set_custom_column_metadata(label, *, name, editable, display)` (1.24) edits an existing column's name/editable/display JSON (notably `enum_values`, the only way to populate it outside Calibre); the display dict replaces the stored payload wholesale (upstream parity), a change sets `update_all_last_mod_dates_on_start` like upstream's wrapper, honest no-op on equal values, and there is deliberately NO datatype or label parameter (type changes would strand the storage; the label is the `#label` search token).
- **Format writes keep Calibre's FTS index and page counts honest (1.18).** `add_format`/`set_format` insert the (book, format) pair into the sidecar's `dirtied_formats` and set `books_pages_link.needs_scan` (schema-guarded); `remove_format` clears the queue entry so Calibre never re-extracts a vanished file; `add_book` seeds the same queue per seeded format (upstream's add path queues every data INSERT, 1.20.1) and `remove_book` clears the doomed book's entries alongside `metadata_dirtied`/`annotations_dirtied` (1.20.1). The sidecar is attached as `fts_db` BEFORE the transaction opens (`_ensure_fts_attached`; every batch-opening verb that queues -- set_format, add_format, remove_format, save/restore_original_format, add_book, remove_book -- attaches first, 1.20.1 closed the save_original_format gap) and the queue writes roll back with the batch; a missing/unattachable sidecar degrades to a no-op. (Pre-3.21.0 SQLite builds forbid ATTACH inside a transaction; modern builds allow it, but the attach-first rule is uniform.) NEVER delete from `fts_db.books_text` outside Calibre: its delete triggers tokenize through FTS5 with Calibre's custom tokenizer. The FTS queue verbs (1.24) are the sanctioned queue surface: `fts_reindex_book`/`fts_reindex_all`/`fts_queue_clear` manage `dirtied_formats` only (upstream `dirty_book`/`dirty_existing`/`remove_dirty`/`clear_all_dirty`); upstream `fts_unindex`'s index-row deletion is process-bound by the same tokenizer fact, and stays Calibre's job.
- **`add_book` refuses byte-identical re-imports.** A format seed whose bytes match an already-catalogued `data` row (same format + size pre-filter, then content compare) raises before anything is written, dry runs included: the 'never imported twice' invariant. Richer, metadata-based duplicate screening (ISBN/title/author) stays a frontend concern, not this guard's job.
- **Pubdate is TEXT.** `set_pubdate` stores `datetime.isoformat(' ')` in UTC (naive = UTC); `None` means the `0101-01-01 00:00:00+00:00` undefined-date sentinel. Never write unix integers to date columns.
- **Rows omit comments; two sanctioned reads.** `get_book()`/`get_all_books()` rows never carry comment text (it can be huge). Read it via `get_book(include_comments=True)` or bulk `get_comments()`; raw HTML must pass through `helpers.strip_html()` before rendering.
- **Dirtied queues are read-only on the read side.** `CalibreDB.get_dirtied_books()` and `get_annotations_dirtied_books()` only observe `metadata_dirtied` / `annotations_dirtied`; clearing entries is Calibre's job (`mark_book_as_clean()`). Never DELETE from them in cquarry code.
- **Custom-column writers follow physical layout, not flags.** Detect Pattern A (value table + link) vs B (direct `book` column) by link-table existence; the same rule as the reader. The writers dispatch on datatype (`text`/`enumeration`/`series`/`rating` are Pattern A; `int`/`float`/`bool`/`datetime`/`comments` are Pattern B); unknown datatypes and layout mismatches raise instead of stringifying. Enumerations validate against `display.enum_values` (empty means nothing is writable); rating-typed columns take 0-5 stars, store x2 on the shared 0-10 scale like `set_rating` (0 stars clears, Calibre purges 0 rows), and `field()` surfaces them as stars so both rating kinds compare alike; datetime-typed columns normalize like `set_pubdate` (ISO text in UTC). Non-editable columns raise; composite columns have no storage and raise. `None` entries in value lists are skipped, never stringified into `'None'`.
- **Custom-column lookup takes `#label`, bare label, or display name (1.9).** `find_custom_column()`/`load_custom_column()`: a leading `#` matches the label only; otherwise exact display name wins (the historical key) with bare label as the fallback; label side is case-insensitive like the write module's `_custom_column_meta`. `get_custom_columns()` stays keyed by display name; do not rekey it, consumers iterate it.
- **Entity writes prune orphans AFTER links go.** The fkc_delete_on_* triggers abort while references remain; clean links first, then delete unreferenced entity rows.
- **`mark_for_delete` columns are not filtered on read.** Upstream also selects pending-delete custom columns and purges them at startup; keep `get_custom_columns()` faithful.
- **Some schema objects are Calibre-process-bound, by design.** The `meta` view (`sortconcat`/`concat` aggregates) and `tag_browser_filtered_*` views (`books_list_filter()`) raise `OperationalError` outside Calibre; never read them; `get_tag_browser_counts()` reads the pure-SQL `tag_browser_*` views and supplies `title_sort()` from `helpers` for the duration of that read only.
- **Entity notes are NOT in metadata.db.** Upstream stores them in a separate `<library>/.calnotes/notes.db` attached at runtime; out of scope for this library (do not "fix" that by reading the sibling file).
- **The FTS sidecar is a sanctioned read (1.18).** `full-text-search.db` beside metadata.db is read through `get_book_text(book_id, fmt)` (the full `books_text` row incl. `searchable_text`), `get_text_extractions()` (bulk status rows WITHOUT the texts: err_msg audit + format-hash change detection), and `search_book_text()` (folded Python-side content search -> `{book: {formats}}`). The plain `books_text` table ONLY: the FTS5 index tables tokenize through Calibre's custom tokenizer and are unqueryable outside Calibre, so no FTS5 machinery is ever touched. Same snapshot/lock handling as metadata.db; a missing or uninitialized sidecar degrades to empty (never an error); `refresh()` drops the sidecar connection with everything else.
- **`get_book_dossier()` composes, it does not re-query.** Its pieces are the existing single-purpose APIs (`get_book`, `get_formats`, `get_cover_path` with defaults, `field()` for custom columns); change those and the dossier follows. Custom-column values are keyed `#label` from `get_custom_columns()`'s display-name entries; the label comes from the VALUE's `label` field, not the dict key.
- **`integrity`/`analytics` are pure over the cache.** They take a `CalibreDB`, never a path; no SQL of their own (the cover-file checks are the sanctioned exception, riding `get_cover_path` + `get_image_size`). Frontends render; these modules only derive. Don't add a fourth copy of a predicate in a consumer; promote it here.
- **Duplicate screening and flat export rows (1.17).** `CalibreDB.find_candidate_duplicates(title, authors, isbn=None)` is the library half of duplicate screening (ISBN rule, then normalized title + folded first author); the file half stays in the frontend (embedded metadata readers are bindery/CQ territory, not this library). `CalibreDB.export_rows()` yields one flat dict per book with custom columns as `#label` keys -- consumers must not re-add inline export SQL for what it already covers. `integrity.find_identifierless()` joins the predicate family.
- **Calibre schema facts worth remembering** (from the retired `database_report.md`): link tables are asymmetric -- `books_authors_link` is N:M (`UNIQUE(book, author)`) while `books_publishers_link`/`books_series_link` are 1:N (`UNIQUE(book)`); annotations search is backed upstream by FTS5 siblings (`annotations_fts`, `annotations_fts_stemmed`) which cquarry deliberately does not read; a stored annotation's notes follow its highlighted text joined by `\n\x1f\n` (LF, unit separator, LF) inside `searchable_text` -- split on that byte sequence, never on a bare newline; and the `identifiers` EAV is `UNIQUE(book, type)`, which is why plugins invent pseudo-types like `isbn13` instead of a second value.
- **`tag_rollup` is subtree totals** (own count + everything below), matching Hermitage's `_total_count` and Carrel's category union so adoption is render-identical. The Phase 9 roadmap's example showed a keyed node keeping its bare count; that example was corrected when this shipped (1.8.0).

## Layout
- `src/cquarry/db.py`: `CalibreDB` connection management, snapshot fallback for locked databases (since 1.23 a consistent sqlite backup-API copy behind `SNAPSHOT_LEASH`; `backup_to(dest)` is the consumer-facing consistent copy, and `external_changes_detected()` is the PRAGMA data_version staleness token that gates refresh()), schema mapping, Phase-2 extractors (`get_annotations`, its decoded renderer view `get_annotations_decoded` (1.23), the filtered conveniences `get_annotations_filtered` + `get_annotation_users`/`get_annotation_types`/`get_annotation_styles` (1.25; tombstones hidden by default, style discovery covers only what the library holds), `get_last_read_positions`, `get_plugin_data`, `get_conversion_profiles`; the annotations: search text bulk-loads since 1.23 -- no per-book N+1), single-entity APIs (`get_book`, `search_books`, `get_format_path`, `get_book_by_uuid` (1.24, the Calibre-Companion lookup), `get_all_formats` (1.24, the cached bulk formats map), `get_entity_book_ids` (1.24, the id-set half of get_entities; tags are the engine's anchored-subtree rule)), read-side coverage (`get_dirtied_books`, `get_annotations_dirtied_books`, `get_feeds`, the FTS sidecar reads `get_book_text`/`get_text_extractions`/`search_book_text`/`get_dirtied_formats` (1.24), `get_tag_browser_counts`, `get_formats`, `get_cover_path`, `get_cover_bytes`/`get_cover_last_modified` (1.25, the web-frontend bytes/mtime pair riding get_cover_path's resolution), `read_backup` (1.25, Calibre's stored sidecar OPF as bytes, for diffing its last write against the rows; reads what Calibre wrote, the OPF-generation decline untouched), `get_size_stats`/`is_fts_enabled`/`get_all_link_maps_for_book` (1.25, the XS tail: file sizes with notes always 0 per the recorded decline, the fts_enabled preference -- in-process pool state is not database-visible, and the four-field-plus-custom per-book link map; the custom link map is stashed for EVERY normalized column since the 1.25 series-only-stash fix), `format_hash`/`format_metadata` (1.25, the file-changed detector the FTS sidecar's hash columns compare against; rides get_format_path's verified resolution and errors), `books_by_year`/`books_by_month` (1.25, any-date-field buckets -- builtin date locations plus date-typed custom columns, restriction-shaped; the 0101/0100 sentinels bucket nowhere, hunting them stays find_sentinel_pubdates' job), `get_next_series_num_for` (1.25, the preference-aware next number for the builtin series or a series custom column; the `series_index_auto_increment` setting reads from the library's preferences table with upstream's shipped default "next" -- upstream's tweaks files are process-side and invisible here; document that boundary, don't "fix" it), `virtual_libraries_for_books` (1.25, the inverse VL map; ## Testing
Run with the source tree on the path so you exercise this repo, not a stale installed copy:
```sh
PYTHONPATH=src python -m pytest tests/ -q
```
(The bare `python -m pytest` picks up whatever cquarry is pip-installed in the environment; check its version if results look stale.)

## Cross-Repo Implementation Rule
If any major update or new feature is added to `cquarry`, you MUST immediately assess and implement it throughout `~/.gitrepos/CalibreQuarry`, `~/.gitrepos/bindery-cli`, and `~/.gitrepos/Hermitage` if the update logically fits their respective domains. Keep the entire Calibre ecosystem synchronized with `cquarry`'s latest capabilities.
