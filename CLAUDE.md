# CLAUDE.md (cquarry)

Per-project guidance. Overrides the global file where they conflict.

## What this is
The canonical SQLite database layer and search grammar engine for Calibre; every read path is strictly read-only, and writes exist only behind the explicit opt-in `cquarry.write` module. Extracted from CalibreQuarry to serve as a shared backend for Hermitage, Wings (Carrel), Bindery, and the CalibreQuarry CLI.

## Hard constraints
- **No external dependencies.** Must run on pure Python 3.14+ standard library (`sqlite3`, `re`, `json`).
- **Read-only by design.** `CalibreDB` NEVER writes to `metadata.db`. The only sanctioned mutation path is the separate opt-in module `cquarry.write.WritableCalibreDB`; never add write methods to `CalibreDB`, and never import `cquarry.write` from read-only code.
- **Perfect Parity.** `cquarry.search.SearchEngine` must behave exactly like Calibre's native search bar. This includes edge cases like implicit AND evaluation, dot-delimited hierarchical tag search, identifier routing, exact match prefixing (`=`) with `.`/`..` component modifiers on every text field, multi-valued count operators (`tags:#>3`), language canonicalization, and strict errors for unknown virtual libraries / saved searches. Documented deviations live in spec.md §5; do not silently add more.
- **Performance.** `get_all_books()` executes an optimized 6-JOIN query over `books` and hydrates the list-typed fields in Python, then caches it. `SearchEngine` queries the cache, rarely the disk.

## Programmer-facing contract notes
- **List-typed fields.** `get_all_books()` / `get_book()` expose `authors`, `tags`, `languages`, `formats` as native `list[str]` (never comma-joined strings). Downstream code must NOT `.split(",")` them. Multi-valued custom columns are native lists end to end too (1.16): `field()` and `load_custom_column()` return `list[str]`, and `set_custom_column` treats a bare string as ONE value rather than comma-splitting it, so `Doe, John` survives as a single value.
- **Rows include `size`, `uuid`, `identifiers`.** `get_book()` and `get_all_books()` rows are shape-identical: both carry `size` = SUM(data.uncompressed_size) (may be None on odd schemas), per-book `uuid` ("" on schemas predating the column), and the `identifiers` EAV dict. Never add a field to one and not the other.
- **Languages follow `item_order`.** A book's `languages` are ordered by `books_languages_link.item_order` (link-id tiebreaker); pre-`item_order` schemas degrade to link-id order; Calibre's ordering contract.
- **Strict VL/saved-search errors.** `search("vl:X")` raises `ParseException` when X is unknown; only `resolve_vl()`/`resolve_saved_search()` raise `ValueError` with an available-names message. Unknown field locations and unknown `@Names` match NOTHING (empty set); never an `all:` text sweep; that is upstream behavior too. Corrupt or non-dict `virtual_libraries`/`saved_searches` preference payloads degrade to empty dicts (1.16); reads never crash on them, and ancient schemas missing the `identifiers`/`comments` tables degrade on `get_book()`/`search()` exactly like `get_all_books()` does.
- **`refresh()` is the coherence boundary.** All caches are lazy and normally never invalidate; a long-lived holder (Hermitage/Carrel keep a connection open) must call `refresh()` after an external write or its caches contradict each other (and the database). New caches must be added to `_init_caches()` so `refresh()` covers them.
- **`#label_index` is real for custom series columns (1.18).** `load_custom_column` selects the link table's `extra` float and stashes it under the derived `#<label>_index` token; `_custom_value` resolves the suffix against the base series column, so `#myseries_index:>3` matches. An exact label literally ending in `_index` keeps the token (exact labels always win); ancient link tables without `extra` degrade to None. The normalized value tables' `link` URL column rides the same SQL: read it via `custom_column_links(col_name)` -> `{book: url}`, never by folding it into load_custom_column's contract-frozen return.
- **User categories search via `@Name`.** `@Name:query` mirrors upstream `get_user_category_matches` (exact match on each member's own location; leading `.` includes subcategories; `false` inverts; other query text ignored; <2-char queries match nothing). Groups and real fields win over same-named categories. Providers opt in via the optional `user_categories()` hook.
- **Raw comments are HTML.** Anything rendered must pass through `helpers.strip_html()` first.
- **Writes must queue OPF resync.** Every `WritableCalibreDB` mutation inserts the book id into `metadata_dirtied` (Calibre regenerates sidecar `.opf`s only for queued ids). New write APIs MUST route through `_touch_book()`/`_mark_dirty()`; never bump `last_modified` alone.
- **`batch()` owns the commit inside its block.** Inside `with wdb.batch():`, setters defer their per-call commit and skip their own rollback; any failure rolls back the whole pass, and the failure poisons the pass: an inner batch's exception caught by the caller still rolls back at the outermost exit, never commits. `_begin()`/`_commit()`/`_rollback()` guard on `_batch_depth`; new setters get this for free by using the helpers. Never call `self.conn.commit()` directly in a setter. `transaction()` is the kept pre-1.7 alias of `batch()` (restored in v1.7.1 after a phase-3 import hit `AttributeError` on the missing name); prefer `batch()` in new code. Rollback paths catch `BaseException` (a Ctrl-C mid-set unwinds instead of committing a torn edit), and outside a batch the context-manager exit rolls back whenever an exception is in flight; its commit failures propagate like `batch()`'s do.
- **Filesystem compensation is batch-scoped.** `add_book` tracks the directories it creates inside the current outermost `batch()`; a failed outermost exit removes them all (rollback alone would strand earlier books' directories as orphans). Adds made outside any batch never register, so a later failed batch cannot touch committed books' directories. New file-creating write APIs must follow the same rule: register on `_batch_dirs`, compensate only at the outermost exit.
- **`remove_book`'s file story (1.17).** `delete_files=None` (default) is rows-only; `"trash"` moves the book directory into the library-local `.caltrash/b/<id>/` (upstream's own layout), `"permanent"` rmtree's it. The fs step lands only after the rows COMMIT; inside a `batch()` it defers to the outermost commit via `_pending_removals`, so a rollback never leaves resurrected rows fileless. New file-removing APIs must follow the same commit-then-fs rule.
- **`set_format` (1.17).** Sanctioned remove+add of one `data` row in a single transaction (honest no-op when identical); the file swap stays the caller's atomic-replace job.
- **`add_book` refuses byte-identical re-imports.** A format seed whose bytes match an already-catalogued `data` row (same format + size pre-filter, then content compare) raises before anything is written, dry runs included: the 'never imported twice' invariant. Richer, metadata-based duplicate screening (ISBN/title/author) stays a frontend concern, not this guard's job.
- **Pubdate is TEXT.** `set_pubdate` stores `datetime.isoformat(' ')` in UTC (naive = UTC); `None` means the `0101-01-01 00:00:00+00:00` undefined-date sentinel. Never write unix integers to date columns.
- **Rows omit comments; two sanctioned reads.** `get_book()`/`get_all_books()` rows never carry comment text (it can be huge). Read it via `get_book(include_comments=True)` or bulk `get_comments()`; raw HTML must pass through `helpers.strip_html()` before rendering.
- **Dirtied queues are read-only on the read side.** `CalibreDB.get_dirtied_books()` and `get_annotations_dirtied_books()` only observe `metadata_dirtied` / `annotations_dirtied`; clearing entries is Calibre's job (`mark_book_as_clean()`). Never DELETE from them in cquarry code.
- **Custom-column writers follow physical layout, not flags.** Detect Pattern A (value table + link) vs B (direct `book` column) by link-table existence; the same rule as the reader. The writers dispatch on datatype (`text`/`enumeration`/`series`/`rating` are Pattern A; `int`/`float`/`bool`/`datetime`/`comments` are Pattern B); unknown datatypes and layout mismatches raise instead of stringifying. Enumerations validate against `display.enum_values` (empty means nothing is writable); rating-typed columns take 0-5 stars, store x2 on the shared 0-10 scale like `set_rating` (0 stars clears, Calibre purges 0 rows), and `field()` surfaces them as stars so both rating kinds compare alike; datetime-typed columns normalize like `set_pubdate` (ISO text in UTC). Non-editable columns raise; composite columns have no storage and raise. `None` entries in value lists are skipped, never stringified into `'None'`.
- **Custom-column lookup takes `#label`, bare label, or display name (1.9).** `find_custom_column()`/`load_custom_column()`: a leading `#` matches the label only; otherwise exact display name wins (the historical key) with bare label as the fallback; label side is case-insensitive like the write module's `_custom_column_meta`. `get_custom_columns()` stays keyed by display name — do not rekey it, consumers iterate it.
- **Entity writes prune orphans AFTER links go.** The fkc_delete_on_* triggers abort while references remain; clean links first, then delete unreferenced entity rows.
- **`mark_for_delete` columns are not filtered on read.** Upstream also selects pending-delete custom columns and purges them at startup; keep `get_custom_columns()` faithful.
- **Some schema objects are Calibre-process-bound, by design.** The `meta` view (`sortconcat`/`concat` aggregates) and `tag_browser_filtered_*` views (`books_list_filter()`) raise `OperationalError` outside Calibre; never read them; `get_tag_browser_counts()` reads the pure-SQL `tag_browser_*` views and supplies `title_sort()` from `helpers` for the duration of that read only.
- **Entity notes are NOT in metadata.db.** Upstream stores them in a separate `<library>/.calnotes/notes.db` attached at runtime; out of scope for this library (do not "fix" that by reading the sibling file).
- **The FTS sidecar is a sanctioned read (1.18).** `full-text-search.db` beside metadata.db is read through `get_book_text(book_id, fmt)` (the full `books_text` row incl. `searchable_text`), `get_text_extractions()` (bulk status rows WITHOUT the texts: err_msg audit + format-hash change detection), and `search_book_text()` (folded Python-side content search -> `{book: {formats}}`). The plain `books_text` table ONLY: the FTS5 index tables tokenize through Calibre's custom tokenizer and are unqueryable outside Calibre, so no FTS5 machinery is ever touched. Same snapshot/lock handling as metadata.db; a missing or uninitialized sidecar degrades to empty (never an error); `refresh()` drops the sidecar connection with everything else.
- **`get_book_dossier()` composes, it does not re-query.** Its pieces are the existing single-purpose APIs (`get_book`, `get_formats`, `get_cover_path` with defaults, `field()` for custom columns); change those and the dossier follows. Custom-column values are keyed `#label` from `get_custom_columns()`'s display-name entries; the label comes from the VALUE's `label` field, not the dict key.
- **`integrity`/`analytics` are pure over the cache.** They take a `CalibreDB`, never a path; no SQL of their own (the cover-file checks are the sanctioned exception, riding `get_cover_path` + `get_image_size`). Frontends render; these modules only derive. Don't add a fourth copy of a predicate in a consumer; promote it here.
- **Duplicate screening and flat export rows (1.17).** `CalibreDB.find_candidate_duplicates(title, authors, isbn=None)` is the library half of duplicate screening (ISBN rule, then normalized title + folded first author); the file half stays in the frontend (embedded metadata readers are bindery/CQ territory, not this library). `CalibreDB.export_rows()` yields one flat dict per book with custom columns as `#label` keys -- consumers must not re-add inline export SQL for what it already covers. `integrity.find_identifierless()` joins the predicate family.
- **Calibre schema facts worth remembering** (from the retired `database_report.md`): link tables are asymmetric -- `books_authors_link` is N:M (`UNIQUE(book, author)`) while `books_publishers_link`/`books_series_link` are 1:N (`UNIQUE(book)`); annotations search is backed upstream by FTS5 siblings (`annotations_fts`, `annotations_fts_stemmed`) which cquarry deliberately does not read; a stored annotation's notes follow its highlighted text joined by `\n\x1f\n` (LF, unit separator, LF) inside `searchable_text` -- split on that byte sequence, never on a bare newline; and the `identifiers` EAV is `UNIQUE(book, type)`, which is why plugins invent pseudo-types like `isbn13` instead of a second value.
- **`tag_rollup` is subtree totals** (own count + everything below), matching Hermitage's `_total_count` and Carrel's category union so adoption is render-identical. The Phase 9 roadmap's example showed a keyed node keeping its bare count; that example was corrected when this shipped (1.8.0).

## Layout
- `src/cquarry/db.py`: `CalibreDB` connection management, snapshot fallback for locked databases, schema mapping, Phase-2 extractors (`get_annotations`, `get_last_read_positions`, `get_plugin_data`, `get_conversion_profiles`), single-entity APIs (`get_book`, `search_books`, `get_format_path`), read-side coverage (`get_dirtied_books`, `get_annotations_dirtied_books`, `get_feeds`, the FTS sidecar reads `get_book_text`/`get_text_extractions`/`search_book_text`, `get_tag_browser_counts`, `get_formats`, `get_cover_path`, `get_library_uuid`, native `pages` via `books_pages_link`, its provenance columns via `get_page_metadata`, entity secondary columns via `get_entities`; kinds: authors/series/publishers/tags/languages/ratings, typed preferences via `get_preference`/`get_field_metadata`/`get_user_categories`/`get_tag_browser_state`), and the composed reads (`get_book_dossier`, `format_path_index`/`find_book_by_path`, `list_books` — the paginated sorted listing frontends page over).
- `src/cquarry/search.py`: Lexer, AST Parser, and Evaluator for Calibre's search grammar (incl. saved-search interpolation, count operator, lang canonicalization, grouped search terms, `@Name` user categories).
- `src/cquarry/helpers.py`: Common domain-specific logic (star ratings, JPEG/PNG header sniffing, author normalization, `strip_html`, `tags_to_tree`, `tag_rollup`, `title_sort`; the stdlib Calibre title-sort key, reused by `write.register_udfs()` and `get_tag_browser_counts()`; the ISBN family: `isbn_normalize`, `isbn_check_digit_is_valid`, `to_isbn13`).
- `src/cquarry/integrity.py`: Pure library-integrity predicates over the cached rows (`find_untagged` … `find_series_gaps`). No SQL of their own; cover-file checks ride `get_cover_path` + `get_image_size`.
- `src/cquarry/analytics.py`: Pure derivations over the cached rows (`addition_timeline`, `author_stats`, `rating_distribution`, `vl_overlap`). Formatting stays in the frontends.
- `src/cquarry/write.py`: Opt-in `WritableCalibreDB` + `register_udfs()` for trigger-safe writes, plus the set-write conveniences (`clear_tags`, `clear_rating`, `add_custom_column_values` for is_multiple Pattern-A columns). Separate module by design (spec §3.6).
- `src/cquarry/config.py`: Default path configuration.
- `tests/`: Extensive unit tests imported from the original CalibreQuarry repository.
- `API.md`: The full per-method reference (moved out of the README in 1.8.0); keep it in sync when the API changes.

## Testing
Run with the source tree on the path so you exercise this repo, not a stale installed copy:
```sh
PYTHONPATH=src python -m pytest tests/ -q
```
(The bare `python -m pytest` picks up whatever cquarry is pip-installed in the environment; check its version if results look stale.)

## Cross-Repo Implementation Rule
If any major update or new feature is added to `cquarry`, you MUST immediately assess and implement it throughout `~/.gitrepos/CalibreQuarry`, `~/.gitrepos/bindery-cli`, and `~/.gitrepos/Hermitage` if the update logically fits their respective domains. Keep the entire Calibre ecosystem synchronized with `cquarry`'s latest capabilities.
